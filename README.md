# ひと切り半分こ 〜果物編〜

「ひと切り半分こ」シリーズの果物編です（今後、野菜編・乗り物編などへの展開を想定）。

立体の果物をいろいろな角度から観察し、スワイプの一刀で **体積を 50:50** に切り分ける 3D ブラウザゲームです。
リンゴ → 柿 → メロン → 洋梨 → パイナップル → 桃 → スイカ → バナナ（1房・5本）→ さくらんぼ（2つ連結）→ ぶどう（一房）の全 10 ステージ。成功すると次の果物へ進み、失敗すると同じ果物に再挑戦します。時間制限はありません。

- スマホ縦画面が主対象です。PC のマウスでも遊べます（PC では中央に縦長の画面として表示）。
- 3D 描画は Three.js、UI は HTML/CSS、効果音は Web Audio API で合成しています。

## 起動・ビルド

```bash
npm install
npm run dev        # 開発サーバ（--host 付き。同じ LAN のスマホからも開ける）
npm run build      # 型チェック（tsc）+ dist/hanbunko-fruits/ へビルド
npm run preview    # ビルド結果の確認
npm test           # 単体テスト（体積計算・切断・判定）
npm run e2e -- http://localhost:5173/   # ブラウザでの動作確認（dev か preview を起動した状態で）
npm run deploy     # ビルドして Cloudflare Workers へデプロイ
```

## 操作

| 操作 | 内容 |
| --- | --- |
| 回転パッドを左右にドラッグ | 果物を左右に回す |
| 回転パッドを上下にドラッグ | 果物を上下に回す |
| 指を離す | 回転が止まり、その姿勢を保つ（慣性なし） |
| 「姿勢を戻す」ボタン | 初期姿勢に戻す |
| 失敗後の「もう一度」 | 切ったときの角度のまま再挑戦できる |
| 果物の表示領域をスワイプ | 切る（指を離した瞬間に確定） |
| 右上のスピーカー | 音のオン・オフ（設定は保存） |
| PC のみ：矢印キー / R | 回転 / 姿勢リセット |

- 回転（下のパッド）と切断（上の表示領域）は操作する場所で区別するので、モード切り替えはありません。パッドで始めたドラッグは、果物の上まで指が来ても回転のままです。
- 切断線は、指の軌跡が曲がっていても **始点と終点を結ぶ直線** です。ドラッグ中は光る刃の軌跡と、切断線の目安（点線）が出ます。
- 次の操作では切れません（理由を短く表示します）
  - タップやごく短い動き（表示領域の短辺の 14% か 40px の長い方より短い）
  - 果物の上から始める・果物の上で離す（果物の外から始めて外で離す）
  - 果物を横切らない（始点と終点を結ぶ線が果物のシルエットに触れない）

## ゲーム仕様

- 誤差 = |片側の体積 / 全体の体積 × 100 − 50|。**誤差 1.0% 以内で成功**（49:51 は成功、48.9:51.1 は失敗）。
- 体積比は小数第 1 位まで表示し、判定も **表示と同じ丸めた値** で行います（`src/judge.ts`）。割合を 0.1 単位の整数に丸め、その整数で誤差としきい値を比べます。もう片側は 100 から引いて求めるので、表示の合計は必ず 100.0 になり、「表示では成功範囲なのに失敗」は起きません。
- 切る前に体積比や正解の位置は表示しません。
- 体積には皮・芯・種・種の空洞を含む果実本体を数え（桃・さくらんぼの種も含む）、**枝・ヘタ・葉（柿のがく、パイナップルの冠芽、桃の葉、バナナの柄と房の付け根、さくらんぼの柄、ぶどうの房の枝など）は除外** します。除外した部分も表示上は一緒に切れます。
- バナナ（5本）・さくらんぼ（2粒）・ぶどう（一房）は全体が対象です。切断平面の両側にある「切れていない部分」と「切れた部分」をすべて合計します。それぞれの実は重ならないように配置しています（テストで確認）。
- 結果は切断平面の両側のグループとして、画面の左（横切りなら上）のかけらを先に表示します。
- 全ステージ成功でクリア画面（果物ごとの挑戦回数と成功時の誤差）を出し、「最初から遊ぶ」で再プレイできます。
- 観察する意味を作るため、リンゴ・柿・洋梨・桃・パイナップルは片側が張り出したり上下で太さが違ったりする非対称な形にしています。メロン・スイカは比較的素直な形ですが、片方の端が少し太い卵形です。さくらんぼは2粒の大きさが違います。どの果物も、初期姿勢のまま中心を縦・横に切ると 1% を超えてずれるように初期姿勢を選んでいます。

## 切断と体積計算の方式

表示・切断・体積判定は **同じ三角形メッシュ**（`src/geometry/mesh.ts` の `MeshData`）を使います。見た目だけ切る疑似判定ではありません。

1. **形状**：各果物は手続き的に作った閉じたメッシュ（継ぎ目のない多様体）です。リンゴ・柿・メロン・パイナップル・桃・スイカ・さくらんぼ・ぶどうの粒は「中心から見た方向ごとの半径」で決める星形の立体、洋梨は水平断面ごとに中心と半径を決める回転体、バナナは円弧に沿った五角形断面のチューブ（外側の列に3本、反りの内側に2本を重ねて房の付け根に集める）です。
2. **切断平面**：スワイプの始点と終点を通る 2 本の視線を含む平面（= 切断線をカメラの奥行き方向へ伸ばした平面）をワールド座標で作り、その時点の果物の姿勢の逆行列で果物のローカル座標に移します。回転後の見た目と判定は常に一致します。
3. **切断**（`src/geometry/cut.ts`）：平面をまたぐ三角形を辺の交点で分割します。交点は辺ごとに共有するので、断面の境界はすき間なく閉じたループになります。ループを三角形分割（穴あきにも対応）して断面（キャップ）を作ります。ぶどうの粒やリンゴの上のくぼみのように、断面が複数できる場合や穴がある場合も扱えます。
4. **体積**：発散定理で計算します。片側の体積は「切断で残った表面三角形と、平面上の 1 点を頂点とする四面体の符号付き体積の和」です。断面は平面上にあるので寄与は 0 になり、断面の三角形分割に頼らず倍精度で求まります。切断で生じる三角形は元の三角形をちょうど分割したものなので、両側の和は元の体積と一致します。
5. **断面の模様**：断面テクスチャは、断面の各点を果物の形状定義に戻して「表面からの深さ」などを求め、皮・果肉・芯・種の色を決めて生成します（`flesh` 関数）。形と模様は同じ定義から来ているので、皮の厚みや芯の位置が形と食い違いません。

### 精度の確認（`npm test`）

| 確認 | 結果 |
| --- | --- |
| 球を高さ h で切った割合と解析解（球冠の公式） | 差 0.05% 未満 |
| 切断前後の体積の保存（各果物 40 平面） | 0.001% 未満（ブラウザでの実測は 1e-13 程度） |
| 断面を含めた閉じたかけらの体積 = 断面に頼らない計算 | 1e-3% 未満（断面が正しく閉じている） |
| メッシュを 2 倍細かくしたときの体積比の差（各果物 30 平面） | 最大 0.021%（ぶどう）、他は 0.01% 未満 |
| ぶどう：房ごと切った片側 = 粒ごとに切った片側の合計 | 一致（切れていない粒も含まれる） |
| バナナ5本・さくらんぼ2粒が互いに重ならない | 重なりなし（合計体積が二重に数えられない） |
| 判定：表示値と判定の一致、境界値（48.95→49.0 成功 / 48.94→48.9 失敗） | 一致 |

メッシュは本物の果物の近似ですが、ゲームが判定する対象は画面に表示しているメッシュそのものです。解像度による差は 0.02% 程度なので、1% 判定への影響はありません。

ブラウザでは `window.__game.verify()` が、直近の切断を **別の実装**（ワールド座標に変換した三角形を平面で切り取り直す）で検算し、判定との差と「断面の頂点が画面上でスワイプの直線からどれだけ離れているか（px）」を返します。

## 演出

1. スワイプ中：白い芯のある光の軌跡、火花、切断線の目安。軌跡の速さに応じた風切り音。
2. 切断確定：まっすぐな斬撃が画面を横切って光り、「シャキン」（金属的な倍音＋高域ノイズ）と果物ごとの「サクッ」（リンゴ・柿はシャキッ、洋梨・桃・バナナはやわらかく、メロン・パイナップル・スイカはみずみずしく、さくらんぼ・ぶどうはプチプチ）。光った画面を 1 フレーム描いてから実際の切断を行うので、その処理時間とヒットストップで手応えを出します。
3. 切断直後：かけらが離れながら、断面がカメラへ向くように少し傾きます。傾ける軸は断面のいちばん奥の点に置き、傾けたあとのかけらが切断平面をまたがないよう実際の頂点で測って押し離すので、奥でつながって見えることはなく、2つのかけらの間には必ずすき間（`fx.separateGap`）が空きます。断面全体が果物の色で強く光り、点光源が一瞬周りを照らし、断面から光の粒があふれます。ぶどうは刃が通った粒の断面が一斉に紫色に、さくらんぼは赤く輝きます。
4. 結果：約 1.3 秒で発光が落ち着き、本来の果肉や種が見える状態で体積比を表示します。
5. 成功時のみ：光の輪と果物に対応した色の粒子、「成功！」、チャイム。ボタンは少し間をおいてから押せます。失敗でも 1〜4 の演出は同じです。

## 素材の役割

画像・音声ファイルは使っていません（読み込みに失敗する外部素材がない構成です）。

| 素材 | 作り方 | 役割 |
| --- | --- | --- |
| 果物の形 | 手続き的なメッシュ | 表示・切断・体積判定の共通データ |
| 皮の模様 | 頂点色 + GLSL（ノイズ・ボロノイ） | リンゴの斑点と縞、メロンの網目（凹凸付き）、パイナップルのらせん状の目（凹凸付き）、桃の赤みとうぶ毛、スイカのしま、バナナの斑点、洋梨のそばかす |
| 断面 | 形状定義から生成するテクスチャ | 皮・果肉・芯・種・空洞。切るたびにその平面で生成 |
| 照明 | Three.js の RoomEnvironment + ライト | ツヤと立体感 |
| 光の演出 | シェーダー（加算合成）+ ブルーム | 刃の軌跡、斬撃、断面の発光、粒子、光の輪 |
| 効果音 | Web Audio API で合成 | 風切り音、切断音（果物ごと）、成功・失敗、UI |
| アイコン | `public/favicon.svg`（包丁） | ブラウザのタブ |

- 音は最初のユーザー操作（「はじめる」など）で有効になります。AudioContext が使えない環境でも、音なしでそのまま遊べます。localStorage が使えない場合はミュート設定を保存しないだけです。
- WebGL が使えない環境では、その旨を表示します。

## スマホでの負荷対策

- devicePixelRatio は最大 2。平均フレーム時間が 24ms を超えると、解像度を段階的に下げます。
- ブルームは半分の解像度で処理し、粗いぼかし段の重みを下げて画面全体が霞まないようにしています。
- パーティクルは上限 1800 個の使い回しです。
- 断面テクスチャはタッチ端末では 256px にしています。生成時間は開発用の PC で 384px のとき 20〜60ms、256px ならその約半分です。
- 次のステージの形状は前もって生成しておきます。

## 制約

- 動作確認はヘッドレス Chrome（スマホ縦画面の 390×844 と 360×640、PC の 1280×800、横向き 844×390、タッチ操作の模擬を含む）で行いました。公開版（game.chozo.net/hanbunko-fruits/）は、スマホ実機でも動作・描画・音に問題がないことを確認しています（2026-10-04）。
- 切断の手応え（ヒットストップ）の長さは、端末の処理速度によって多少変わります。
- 体積は表示しているメッシュに対して厳密ですが、実際の果物の比重の違い（空洞・果汁など）は考慮しません。
